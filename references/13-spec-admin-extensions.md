# 13 · 어드민 확장 — 관리 기능 카탈로그와 제안 절차 (모드 ⑤)

## 절차
1. 관리 지점 추출. 00-detect 결과를 재료로 세 질문을 던진다.
   - 표마다: "운영자가 이 표를 보고 무엇을 결정하나?" (예: 신청자 표 → 누구에게 알림을 보낼지)
   - 랜딩·폼마다: "운영 중 무엇을 바꾸고 싶어질까?" (예: 오픈 상태, 가격, 문구, 마감)
   - 코드 상수·환경변수마다: "배포 없이 바꿔야 할 값인가?" (예: 회차 크기, 상한, 기간)
2. 아래 카탈로그와 대조해 프로덕트에 맞는 것만 고른다. 항목마다 "왜 필요해 보이는지"를 파악 근거와 함께 한 줄로 쓴다. 카탈로그에 없어도 프로덕트에 필요하면 EXT-99 로 제안한다.
3. AskUserQuestion 한 번(다중 선택). 선택지 첫 줄은 추천, 마지막은 "지금은 없음".
4. 고른 기능마다 화면 + 서버 API + (필요 시) 마이그레이션을 한 세트로 만든다. 12-spec-security A절을 전부 적용한다. 기능 하나마다 커밋·push. 끝나면 50-report-templates 의 인수인계에 추가한다.

## 카탈로그
| ID | 기능 | 언제 제안하나 | 최소 명세 | 보안 조건 |
|---|---|---|---|---|
| EXT-01 | 신청자 명단 | 전환 표에 개인정보가 있을 때 (거의 항상) | /tools/people: 검색(이름·연락처 뒷자리), 필터(기간·채널·동의), 페이지네이션, 상세 펼치기 | 비밀번호 필수. 연락처 마스킹 기본(010-****-1234), 펼치기는 클릭. 삭제 없음 |
| EXT-02 | 알림 발송 대상 추출 | 마케팅 동의 컬럼이 있을 때 | 조건(동의=true, 기간, 채널) → 건수 미리보기 → CSV 내보내기 | 내보내기마다 {{prefix}}_exports 에 누가·언제·조건·건수 기록 |
| EXT-03 | 캠페인 상태·설정 | 상태값·가격·상한·기간이 코드 상수나 환경변수에 있을 때 | {{prefix}}_settings 1행 + /tools/settings 화면(현재값·변경·변경 이력) | 변경은 감사 로그(EXT-06)에 기록. 파괴적 값(상한 0 등)은 이중 확인 |
| EXT-04 | 중복·스팸 표시 | submit_count, ip_hash, 허니팟이 있을 때 | 명단에 배지(재제출 N회, 같은 IP 다수), 필터 | 표시만. 자동 삭제·차단 없음 |

| EXT-06 | 감사 로그 | 어드민에 쓰기 기능이 하나라도 있으면 항상 | {{prefix}}_audit(actor, action, target, before, after, at) + /tools/audit 읽기 화면 | 로그는 수정·삭제 불가(권한 회수) |
| EXT-07 | 이벤트·회차 운영 | 회차·추첨·예약 슬롯 같은 운영 단위가 있을 때만 | 현재 회차·마감·다음 회차 열기 | 마감·종료는 이중 확인 + 감사 로그 |

| EXT-09 | 백업 내보내기 | Supabase 무료 플랜일 때 | 표별 CSV 내보내기 버튼 + 마지막 내보낸 시각 | 내보내기 기록(EXT-02와 같은 표) |

④ EXT-06 감사 로그 — 위 셋에 쓰기가 생기므로
지금 만들 것을 골라 주세요. (여러 개 선택 가능 / 지금은 없음)"
