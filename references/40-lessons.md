# 40 · 실제로 부딪힌 함정 12개

실제 구현·배포 중에 걸렸던 문제들이다. 증상 → 원인 → 조치 세 줄로 적는다. 같은 증상을 보면 먼저 여기를 본다.

1. **초기 이벤트가 GA 에 안 보임**
   증상: `landing_view` 처럼 맨 처음 쏘는 이벤트가 GA 실시간 보고서에 전혀 안 뜬다.
   원인: gtag 초기화(`next/script afterInteractive`)가 React 하이드레이션보다 늦게 끝나서, `useEffect` 에서 쏜 이벤트가 `gtag` 없는 상태로 plain object 로 버려진다.
   조치: gtag 스텁 + `config` 호출을 `<head>` 인라인 `<script>` 로 옮긴다(24-impl-ga 의 AnalyticsHead).

2. **같은 이벤트가 2번 찍힘**
   증상: GA 이벤트 수가 실제 동작 횟수의 2배로 찍힌다.
   원인: 같은 추적 컴포넌트가 레이아웃과 페이지 양쪽에서 렌더된다.
   조치: 모듈 수준 플래그(또는 `sessionStorage`)로 페이지당 1회만 보내게 막는다.

3. **두 번째 클릭부터 안 세어짐**
   증상: 짧은 링크를 같은 브라우저로 다시 누르면 클릭 수가 그대로다.
   원인: 리다이렉트 응답이 301 이라 브라우저가 캐시해 두 번째부터는 서버에 요청 자체가 안 간다.
   조치: 302 로 바꾸고 `Cache-Control: no-store` 를 같이 보낸다.

4. **클릭 수가 실제보다 부풀어 오름**
   증상: 사람이 누른 것보다 클릭 수가 훨씬 많다.
   원인: 메신저·SNS 의 링크 미리보기 봇이 URL 을 미리 한 번씩 열어본다.
   조치: User-Agent 로 알려진 미리보기 봇을 걸러내고, `HEAD` 요청은 집계에서 제외한다.

5. **GA Data API `invalid_grant` (audience mismatch)**
   증상: 어드민 대시보드의 GA 연동이 OIDC 토큰 교환 단계에서 `invalid_grant` 로 실패한다.
   원인: `getVercelOidcToken` 함수 자체를 `subject_token_supplier.getSubjectToken` 에 바로 넘기면, 라이브러리가 호출 시 넘기는 컨텍스트(audience 포함)가 함수의 옵션 인자로 해석되어 토큰의 `aud` 가 공급자 URL 로 바뀐다.
   조치: `{ getSubjectToken: () => getVercelOidcToken() }` 처럼 인자 없는 화살표 함수로 감싸서 넘긴다.

6. **"IAM Service Account Credentials API has not been used"**
   증상: 서비스 계정 가장(impersonation) 호출이 "API가 사용되지 않았거나 비활성 상태" 오류로 실패한다.
   원인: GCP 프로젝트에서 그 API 를 막 켰거나, 아예 켜지 않았다.
   조치: API 및 서비스에서 활성화하고, 활성화 직후라면 몇 분 정도 전파를 기다린 뒤 다시 시도한다.

7. **Supabase SQL Editor 붙여넣기 실패 · 한글 깨짐**
   증상: `cmd+v` 로 SQL 을 붙이면 첫 번째는 되다가 이후엔 반응이 없고, 한글 문자열이 깨진 바이트로 들어간다.
   원인: 셸의 `LANG` 이 UTF-8 이 아니면 `pbcopy` 가 바이트를 잘못 인코딩하고, 에디터 포커스·클립보드 상태에 따라 두 번째 붙여넣기부터 실패한다.
   조치: `LANG=en_US.UTF-8 pbcopy < file.sql` 로 복사한다. 붙여넣기가 불안정하면 `monaco.editor.getModels().at(-1).setValue(sql)` 로 에디터 값을 직접 주입하고, "Run" 클릭 후 뜨는 "Potential issue" 확인 다이얼로그에서 "Run query" 를 눌러 실행한다. 한글이 들어가는 seed 데이터는 SQL 문자열보다 API(PATCH) 호출로 넣는 편이 안전하다.

8. **GCP 콘솔에서 타이핑이 엉뚱한 곳으로 감**
   증상: 입력창에 값을 치면 검색창이 열리거나 사이드바가 토글되는 등 의도치 않은 동작이 같이 일어난다.
   원인: 포커스가 입력창이 아니라 페이지에 있어 글자가 GCP 콘솔의 키보드 단축키로 해석된다.
   조치: `find` 로 그 입력창의 엘리먼트 참조를 먼저 잡고, `form_input` 으로 값을 직접 설정한다. 그 뒤 스크린샷으로 값을 확인한다.

9. **복사 실패가 저장 실패로 보임**
   증상: 링크를 만들었는데 사용자가 "저장이 안 됐다"고 한다.
   원인: 저장은 성공했지만 `navigator.clipboard.writeText()` 가 권한 거부 등으로 막혀 복사만 실패했는데, 화면에서 둘을 구분하지 않고 하나의 실패 메시지로 보여줬다.
   조치: 저장 성공 여부와 복사 성공 여부를 분리해서 표시한다. 복사만 실패했을 때는 "저장됐고, 복사만 막혔으니 직접 복사하라"고 명확히 안내한다.

10. **Vercel 배포가 Blocked 상태로 멈춤**
    증상: git push 는 됐는데 Vercel 배포가 "Blocked" 로 표시되고 진행되지 않는다.
    원인: 커밋 작성자 이메일이 GitHub 계정에 연결된 이메일과 다르다(예: 다른 도구가 기본 이메일로 커밋).
    조치: 그 저장소 로컬에서만 `git config user.email`을 GitHub 의 noreply 이메일로 맞춘다(전역 설정은 건드리지 않는다).

11. **`vercel env pull` 이 값 대신 `[SENSITIVE]` 를 내려줌**
    증상: 로컬에서 `.env.local` 을 받아 써보면 일부 변수 값이 `[SENSITIVE]` 라는 문자열 그대로 들어있다.
    원인: 통합(연동)이 자동으로 주입하는 시크릿은 Vercel 이 CLI 로는 실제 값을 내려주지 않는다.
    조치: 로컬 개발은 그 값이 없다고 가정하는 폴백 경로(로컬 전용 저장소 등)로 검증하고, 실제 DB 를 만지는 작업은 대시보드(웹 콘솔)에서 한다.

12. **같은 Supabase 프로젝트의 다른 사이트 표를 건드림**
    증상: 전혀 관계없어야 할 다른 사이트의 데이터가 바뀌어 있다.
    원인: 무료 플랜 한도 등으로 여러 사이트가 같은 Supabase 프로젝트를 공유하는데, 표 이름이 비슷해서 착각하고 건드렸다.
    조치: 이 사이트가 쓰는 표에는 반드시 같은 접두사를 붙이고, 그 접두사로 시작하지 않는 표는 "읽지도 쓰지도 않는다"는 규칙을 CLAUDE.md 같은 상시 지침 파일에 명시해 둔다.
